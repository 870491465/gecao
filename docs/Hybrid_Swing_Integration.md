## 运行入口

Creator 等待资源导入后打开 `assets/scenes/Main.scene`。主画面会标明“临时挥刀 · 缺少正式序列帧”。Debug 下点右侧“动画”打开检查面板。

独立入口 `assets/scenes/SwingSequenceLab.scene`：一级、临时进度，默认打开检查面板，**不读取或覆盖 Main 存档**。原 `CatPartsLab.scene` 仍用于六层素材静态与迈步检查，未替换成不合格序列。

面板提供：单次挥刀（当前刀结束后暂停）、循环预览、暂停/继续、下一帧、0.5 秒跨帧、脚底锚点/轨迹/有效命中区、刀光开关、草屑开关、当前帧/阶段、本刀与上刀单元数和金币增量。缺帧时“下一帧”明确改为临时关键相位单步，**不会显示伪造的角色帧编号**。使用播放、单步或调参的场次标记 debug，不混入正常成长统计。

## 显示与时间

`ActorAnchor / CatRoot` 固定在脚底中心 `(0,-205)`，不旋转、不缩放；子节点：

```text
CatRoot
├─ WalkVisual / LayeredCatParts
├─ SwingVisual                     整猫与镰刀 Sprite，当前无正式图，默认隐藏
├─ SlashFX                         独立复用 Sprite，默认关闭
├─ UpgradeHint                     独立头顶锚点
└─ AnimationAnchorsAndTrack         仅开发检查
```

升级卡在 UI 下的 `UpgradeHintView` 跟随独立 UpgradeHint 锚点，不挂在身体或手臂上。两套角色显示互斥，不交叉淡入两个猫或两把刀。每帧用同一整画布、同一脚底锚点和配置比例显示，关闭 trim；整猫节点角度始终为零。

缺序列时使用 Walk V02 完整六层，以原右臂镰刀一体层做小幅临时挥割；已移除几何工具实例，作业带收窄。合格序列加载后，挥割期间独占显示 SwingVisual，结束再接回六层 WalkVisual。

正式序列示例：蓄力 .20、挥割 .20、余势 .15、序列内回收 .17，共 .72 秒；随后 .28 秒回到分层迈步，合计约 1 秒。回收与衔接合计仍为 .45 秒。地图到 .72 才开始平滑推进；推进曲线两端速度为零，步态由真实推进距离驱动，在下一次换到序列前自然落在固定支撑相位。没有新序列时继续原 .55–1 的推进规则，不改变现有临时收割节奏。

## 如何接正式序列

实际加载文件：[sequence.json](../assets/resources/cat-swing-sequence/sequence.json)。当前 `clips: []`，状态 `MISSING_APPROVED_FRAMES`。**只有此文件会被加载，示例不会自动生效。**

完整禁用示例：[sequence.example.json](../assets/resources/cat-swing-sequence/sequence.example.json)。配置列出的文件名目前不存在；示例轨迹仅由当前几何判定计算，**不是从正式动画测得的数据，也不能拿来代替新图的轨迹标定**。

正式图放在 `assets/resources/cat-swing-sequence/frames/`，PNG 必须整只猫与同一把右手镰刀，固定后上方朝上视角。路径在 JSON 中不带 `.png`，例如 `cat-swing-sequence/frames/charge_01`。

每个等级使用独立 clip：`level:1` 或 `2`。在美术验收后填写：

- `id`、`enabled:true`、`approved:true`、`reviewedBy`；标记不替代实际美术检查。
- `canvas:[宽,高]`、`feetTopLeft:[x,y]`：所有帧一致，不能单帧重新裁剪或改变脚底参考。
- `displayScale`、`bodyHeight`：两者乘积应与 Walk V02 的 `996×0.17=169.32` 设计像素体高一致。示例采用 1024 画布、0.5 缩放，源图体高 338.64 像素；正式素材应按实际量测填写，不能用错误数字绕过验收。
- `hitWindow:[0.2,0.4]`：有效挥割时间，序列其他阶段不结算。
- `frames[]`：`file`、独立 `duration`、`stage`（charge / swing / follow / recover）。允许时长不同，总时长须在 .55–.90 秒，留出一秒周期内的步态衔接。
- 可选 `bladeTrack:[{at,x,y},…]`：`at` 为当前帧内秒数，`x/y` 为**相对脚底的源图像素，Y 向上**；不是左上画布坐标。换算为 `(图内x-脚底x, 脚底y-图内y)`。有效挥割内总体必须有足够显式轨迹点。

程序根据相邻轨迹点区间求各列经过时间，并验证刀刃覆盖当前所有逻辑列、根部纵向容差 8 设计像素；不依赖帧号推测接触。缺图、尺寸不符、轨迹不足、未覆盖田垄、左右手/朝向元数据错误或未验收时，拒绝启用，回到明确标注的临时表现。

素材验收还需逐帧确认：右手始终握同一把镰刀、内凹刃朝拉切区、柄不脱手、刀刃不穿头、双脚站稳、首尾姿势自然接回六层角色。这些不能靠 JSON 标记自动证明。

## 命中、暂停和存档

金币仍只由 `HarvestModel.cut()` 提交，原作物 ID、mask 去重、累计收入、升级扣款和保存入口保持原流程。新增的动画适配器只提供各列命中相位及推进曲线，低帧率仍通过原子步跨区间处理；命中事件按实际时间排序，支持从右向左或从左向右的轨迹。SwingStroke 从当前 ID 和 mask 重建本刀集合，刀光/草屑/金币动画没有发钱接口。

显示完全取样于模型当前 `phase`，不用独立自动循环或动画完成回调。暂停、切后台停止 activeSeconds，因此角色帧、步态与 .12 秒刀光同时冻结；继续不从头播放。后台不补发收入。升级销毁旧角色播放层，清理刀光、草屑与临时金币反馈，仍沿用原一次性购买。

存档版本仍为 2，仅增加可选 `animationProfile` 标识，以便重载已启用序列的相位。旧存档不需要迁移。序列只在当前刀尚未命中且地图站稳时启用；若恢复时对应序列不可用，使用单刀推进桥接，避免已推进地面倒退，结算继续受原 mask 保护。不会重新扣款。

资源仍在异步加载时保留原配置标识与相位，不提前当作“素材缺失”删除标识；角色未就绪时停止收割模拟，加载结束再按保存进度接回。此保护已在实际引擎中检查，等待期间没有推进或发钱。
