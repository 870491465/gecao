# 原素材手臂与镰刀修正

本次撤回 UI 优化时引入的几何手臂、加长杆与几何刀刃。一级、二级重新显示 Walk V02 的完整六层 PNG，右臂、手爪、刀柄、刀刃使用原本同一张 `cat_right_arm_sickle.png`，不拆开拼接、不裁切、不拉长。

仍使用 Creator 3.8.8；Main、ScytheLab、SwingSequenceLab 均使用修正后的主玩法显示。经济数值、行列数、升级价格、自动换垄换轮及存档格式没有修改。

## 修正内容

- 原素材握持层恢复：原画布 571×580，原枢轴 `(137,480)`，局部位置 `(302,410)`，统一局部缩放 `0.8`，按原顺序由身体遮住肩部接缝。
- 猫保持 `0.17` 统一缩放，脚底根节点 `(0,-205)` 固定。待机和迈步时手臂回到原图零角度；临时挥割为 `0° → -35° → -2° → 0°`，只旋转原右臂层，不旋转整猫。
- 一级作业带约 54.92、二级约 60.81 设计像素，中心 X≈80.42，位于猫右前侧。刀幅不足的问题通过收窄作业带处理，不能靠加长手臂或刀柄补齐。
- 一级草簇完整画布显示为 64×64，保留源根部锚点；行距 28，按视口高度计算前方缓冲。二级灰盒作物也缩小到当前工具覆盖范围。三至五级机械不变。
- 切割时间、作物根部位置和调试轨迹都由原 PNG 内刃的采样点及原肩部枢轴计算。二级三列的实际经过顺序为右、中、左，按时间顺序结算。
- 保留上一轮的短序列播放模块和缺素材门禁。禁用示例已改为当前窄作业带的数学示例，仍没有生成或导入正式角色帧。

一、二级暂时共用 V02 的同一张镰刀握持图，正式二级长柄外观也需后续素材，不能再用拉长现有图片冒充。当前是可信的原素材小幅临时动作，不是已完成的大幅挥镰。

## 文件

`assets/scripts/ManualSickle.ts` 集中定义原图比例、暂时动作、刀刃接触与窄作业带；`HybridCatActor.ts`、`Actor.ts` 移除几何工具实例；`Config.ts`、`Field.ts`、`GrassLayout.ts` 对齐田地；`SwingSequence.ts` 与禁用配置示例对齐新的接触目标。历史 `WideScytheActor.ts` 文件保留，但不再由主玩法引用或实例化。

修改前备份：`temp/before-sickle-repair-20261028-190338.zip`。旧存档中的金币和已切 mask 保留，不回退、不重算；显示比例和田地位置按新配置加载。

## 实际验证

Creator 3.8.8 Web 构建成功：[build.json](verification/sickle-repair/build.json)。类型检查、原经济/升级/存档/低帧率测试、原素材一致性、短序列配置测试通过：`./tools/verify.ps1`。

实际 WebGL 检查：[results.json](verification/sickle-repair/results.json)。一、二级均显示六张原分层图，手臂保持原尺寸、锚点和缩放，没有 WideShoulderPivot、WoodenShaft、Forearm 或 SteelBlade 几何节点。一级两个单元增加 2 金币，二级三个单元增加 6 金币；实际刀刃点与作物根部误差小于 0.001 设计像素。暂停时余额、推进、手臂角度和脚底根节点不变。
