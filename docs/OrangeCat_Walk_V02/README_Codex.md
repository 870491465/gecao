本包完整包含 6 张透明 PNG，可替代旧 V0.1 四层包，不必再找旧文件。新生成无脚身体、左腿脚、右腿脚；复用旧包的左臂、右臂与镰刀、尾巴。

- parts_config.json：各 PNG 尺寸、建议支点、相对脚底根节点位置、静态缩放和层级。
- previews/assembled.jpg：静态拼装图。
- previews/walk_loop.gif：离线合成的 1.2 秒原地迈步示意，24 帧，50ms/帧；不是 Cocos 实机或可直接导入的动画文件。
- walk_motion.js：与预览一致的纯数学位移函数，由本地 Codex 接入现有动画系统。

## Cocos 接入

先检查现有项目实际版本，使用项目已有 2D Sprite 流程，不改变引擎版本。创建固定 CatRoot，其位置代表两脚之间的地面中心。按 JSON 导入各层；所有尺寸和位置是设计像素，最终统一缩放 CatRoot。

pivot_px_top_left 为图内左上像素坐标；anchor_normalized_bottom_left 已换算成左下原点的归一化锚点。position_from_feet_root_y_up 是相对 CatRoot 的静态位置，X 向右、Y 向上。图层顺序由后至前：两腿、左臂、右臂与镰刀、身体、尾巴。身体遮住上腿和肩部接缝。保留原始尺寸，不要裁切后丢失偏移。

用新 cat_body 替换旧 cat_body_feet，不能叠加使用，否则会出现四只脚。两条腿独立为 CatRoot 子节点。身体、手臂和尾巴可放在统一 UpperBodyMotion 下，让它们共享轻微起伏；把 JSON 的坐标理解为初始姿态，避免重复叠加父节点偏移。

## 走路与滚动

预览使用左右脚相差半个周期，支撑半周期从前向后移动，摆腿半周期向前返回。每只脚的前后偏移幅度为 12 设计像素，抬脚仅加 5 像素视觉位移，身体起伏不超过 3 像素。只用位移，不靠翻转或变形脚图来模拟步伐。

实际游戏不要用固定计时走路而让地图速度任意变化。对于匀速迈步阶段，同一坐标尺度下：stride=4*A，A=12，因此每周期地图推进 48 设计像素；phase 增量 = 地图真实推进距离 / stride。若使用屏幕像素，先乘上 CatRoot 的统一缩放，或先转换回设计像素。支撑脚局部下降速度应抵消地面滚动相对猫的移动，减少滑步。

小游戏可以先做小步幅走路，再根据作物行距和地图速度调步幅，不要为套用参考数值任意更改金币收益或收割速度。图片没有真实脚部透视变形，预览只验证分层位移结构。

## 接到自动收割状态机

1. 迈步接近：地图推进，按推进距离更新步态。
2. 蓄力：逐渐停地图，双脚在当前落点站稳。不要突然重置 phase 导致脚跳位。
3. 挥刀：脚与地图保持稳定，右臂独立工作。刀碰到才触发原有收割事件；回刀不再结算。
4. 回收：手臂收回，再平滑接续步态与地图滚动。
5. 暂停：冻结地图、步态及工作动作；继续时从原相位恢复。

挥镰仍需要本地制作、调试。本次 GIF 只展示迈步，手臂保持静态，不代表完整“走路—挥镰”循环已经完成。右臂和镰刀仍是一层，只适合初步平面旋转验证；大幅跨身体前方的挥扫需要验证刀刃遮挡和透视，必要时补动作手臂素材。
