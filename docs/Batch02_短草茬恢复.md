# Batch02 短草茬与碎屑恢复

用户指出收割后的程序细茬过小。本次将一级、二级已割区域恢复为 `Grass_Field_Batch02` 提供的三组短草茬原 PNG，移除主玩法中隐藏草茬 Sprite、改画细线的覆盖逻辑。

- `grass_mature_A/B/C.png` 切到同字母 `grass_stubble_A/B/C.png`，保留 512×512 画布、根部锚点 `(0.5,0.0625)`、节点位置和显示尺寸。一级画布仍为 284，二级 218，成熟草大小不变。
- 一行仍拼成一丛草：左右/三段各显示同一贴图的不重叠区域，保留原逻辑单元 ID 和部分切割 mask。刀刃经过对应段后，先倾倒淡出约 0.12 秒，再显示原图短茬。
- 叶片和茎秆继续使用 `fx_leaf.png` / `fx_stem.png` 原图，大小由此前 7–11 调为 10–14 设计像素，每次有效切割 3 片，寿命 0.32 秒，最多 48 片，对象池复用。粒子不改变金币。
- 暂停时停倾倒和碎屑；存档恢复直接显示已结算的短茬，不重新播放特效或发钱。

改动文件：`assets/scripts/Field.ts`（恢复草茬显示）、`GrassSkin.ts`（碎屑大小）、`GrassLayout.ts`（统一碎屑配置）。原 PNG、草大小、角色、刀具、经济、升级与存档格式未改变。

Creator 3.8.8 Web 构建成功（退出码 36）。实际 WebGL 检查短茬 Sprite 已启用、程序细茬绘制已关闭、成熟草与同字母草茬共用 284 画布及根部锚点；叶片/茎秆对象池分别使用原图，显示尺寸为 10 / 12 / 14。已查看收割后的连续草茬画面；暂停、一级两轮 160 金币、二级每刀 6 金币与无重复 ID 检查通过。短时桌面运行约 60 FPS、264 节点。

入口仍为 `assets/scenes/Main.scene`。构建、实际 WebGL 截图与测量数据在 `docs/verification/batch02-stubble-restored/`，以 `build.json`、`results.json` 和 `running.png` 为准。真机及 15 分钟性能未验证。
