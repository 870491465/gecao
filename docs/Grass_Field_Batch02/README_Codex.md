## 草簇锚点与视觉替换

6 张草图使用相同 512×512 画布，根部参考点为左上坐标 (256,480)，归一化左下锚点 (0.5,0.0625)。同字母成熟物和草茬保持相同节点位置、画布尺寸和缩放，切换时只改 SpriteFrame。不要各自按不透明边框重新缩放，否则切换会跳位。

画风采用宽叶片、鲜绿和深绿层次，A/B/C 有高度和轮廓变化。导出时按成熟草的视觉根部宽度调整了草茬宽度，并缩短茬高；它们是成簇视觉对应，不保证每根茎的数量和位置逐根一致。若需要极慢镜头展示逐根断裂，需要后续专门绘制切断帧。

一簇对应一个逻辑收割单元，不按图中每片叶子收费。使用原有唯一收割状态和金币逻辑，特效不重复结算。切割可先用 0.10–0.15 秒围绕根部轻微倾倒、缩短或淡出，再显示短茬；这些时长是联调初值。

## 2D 场景起步参数

先按当前项目锁定版本实现，勿升级引擎或切回 3D。所有作物是 2D 精灵，已有画好的视角，不再把图片贴到斜放的 3D 平面。

参考画面宽 540、高 960 时：完整底图显示宽 540、循环段高 1080；两个逻辑列中心 x≈205、335，纵向行距 54；每簇完整画布显示 170×170。它们只是包内静态预览的参数，可按猫和刀幅调整。

先建少量可见行和缓冲行，不创建整张田的全部 Sprite。邻近行可以有轻微横向偏移，但同一逻辑单元的成熟物和短茬必须共用偏移。先不随机镜像，以免光源方向发生冲突；优先使用 A/B/C 变化。按地面锚点排序，屏幕更下方的作物画在更前方。收割边界处单独检查刀具、手臂、草簇遮挡。

猫的屏幕位置保持固定。地图、成熟草、短茬与边缘使用同一推进距离，短茬继续向下移动，不能一直钉在屏幕上。

## 地面上下循环

ground_scroll 是 768 高原始画面加其上下镜像组成的 1536 高纹理。已检查首尾行相同、中间镜像接点两行相同，避免硬颜色接缝。只支持 Y 方向重复，不承诺横向重复。上下镜像会带来对称纹理，这是当前联调版的取舍，不等于已经完成真机滚动验收。

用两个相同地面段首尾拼接，移动出屏幕后放到队尾；位置用共同偏移量计算，避免误差累计或 1 像素缝隙。不要把原始高 768 段单独拿出来当无缝图。分条版本必须同步移动、保持同一段高度。

换垄优先沿用正常底图，只安排一段没有作物的空地，并短暂淡变遮挡切换。transition_empty_band 是可选空地裁片，只适合有淡变遮罩的过渡，不保证直接硬拼的上下边缘相同。不要把其当作第三种无缝地块。过渡不发金币，不在猫脚下突然刷新成熟草。

## 碎屑

用对象池复用两种碎屑，游戏中先试 5–14 像素左右大小，每次有效切割 3–6 片、寿命约 0.25–0.4 秒；向侧上方飞散后淡出。方向、数量、速度需要实机调整。不要按每根叶子生成大量节点，不把碎屑与金币再次结算绑定。

## 交给本地 Codex

先备份当前可运行版本，在测试场景导入 textures/。按 asset_config.json 建少量双列草田，接入现有固定猫、步态同步、地图滚动和收割事件。保留金币、升级、暂停、存档规则。先确认同字母成熟草与短茬切换不跳位，再测重复滚动、暂停恢复和对象池重用。输出测试录屏和当前尺寸、行距、推进速度供复核。不要把预览 JPG 当游戏背景。
